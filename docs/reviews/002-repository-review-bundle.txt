# Modern Applied Statistics with Go: the bootstrap, in R and in Go

MSDS 431 (Northwestern), Week 8. A research consultancy runs computer-intensive statistics in R and asks
whether moving to Go would be easy and how much cloud cost it would save. This repository answers for one
method, **bootstrap estimation of the standard error of the median**, with the same analysis written in R
and in Go, a check that the two give the same results on the same data, measurements of time and memory,
and a cost estimate from published cloud prices.

Every number in this README is generated by `scripts/readme.sh` from the measurements saved in `results/`
and the prices saved in `prices/`. Nothing is typed by hand.

## Recommendation to the consultancy

**How easy is it to use Go in place of R?** Not as easy as changing languages, because R's standard library
is the statistics. The R analysis is one short script. In Go, the random generator, `sample()`, the median
and the bootstrap loop had to be written and tested (the line counts are under
[Effort](#effort-how-easy-is-it)). There is a Go package for bootstrap confidence intervals, but none that
reproduces R's results, which is what an audit of a migration needs. The work is done once, though, and what
it produced is reusable: a generator that draws exactly what R draws, and a resampling engine that accepts
any statistic.

**When does it make sense to use Go for this method?**

- **Many small or medium jobs** (a pipeline that bootstraps thousands of data sets): yes. Most of R's time
  on a small job is R starting up, and the Go program starts almost instantly. This is where the cost saving
  is largest.
- **Large jobs that can use several cores**: yes. The Go program spreads the resamples over the cores with
  one flag and gives the same result for any number of workers. Base R runs this loop on one core.
- **Large jobs on one core where results must match R number for number**: the gain is real but modest.
  R's `sample()`, `mean()` and `median()` are compiled C; Go, reproducing R's generator step by step, is
  faster by less than a factor of two at the largest size measured. With Go's own generator (the block
  stream) the one-core gain is larger.
- **Exploratory work, one-off analyses, anything that needs a method R already has on CRAN**: stay in R.
  The saving on a single run is a fraction of a cent, and the analyst's time costs more than the computer's.

**How much cloud cost would be saved?** The table under [Cloud cost](#cloud-cost) gives dollars per million
jobs and the percentage saved for each data size, on AWS EC2 at published on-demand prices. The percentage
depends strongly on the size of the job: highest for small jobs, lowest for the largest one-core job. Read
it with its limits: the timings come from a laptop with the same processor architecture as the priced
instances, not from those instances, and nothing was run in the cloud.

## The method

Gelman and Vehtari (2021) list *bootstrapping and simulation-based inference* among the most important
statistical ideas of the past fifty years. The bootstrap (Efron 1979; Efron and Tibshirani 1993) estimates
how much a statistic would vary from sample to sample using only the sample in hand:

1. draw a **resample**: n values from the n observations, with replacement;
2. compute the statistic on the resample;
3. repeat B times; the **standard deviation of the B values** (denominator B − 1) is the bootstrap standard
   error.

It needs no formula for the statistic's distribution, which is why it suits the **median**, whose standard
error has no simple formula for skewed data. It is computer-intensive: B × n random draws and B evaluations
of the statistic. Here B = 1,000, and the mean's standard error is computed on the same resamples as a
check, because for the mean theory gives the answer.

The course's jump-start program (`r/original/run-bootstrap-median.R`, T. W. Miller) is kept unchanged. It
estimates something slightly different: it draws 100 fresh normal samples, averages the bootstrap medians of
each, and reports how that average varies across the samples. The programs in this repository compute the
textbook quantity above, on fixed data files, so that R and Go can be compared run for run.

## The Go side

**Finding packages.** A search of the web, pkg.go.dev listings and Awesome Go for bootstrap resampling in Go
turned up general statistics libraries (for example `gonum.org/v1/gonum/stat`) and one package aimed at
bootstrap confidence intervals (`github.com/Preetam/bootstrap`). None reproduces R's random draws, so none
could show that a Go result equals R's. The engine here is therefore our own, and small.

**The Mersenne Twister.** The assignment suggests <https://github.com/seehuhn/mt19937> so that Go uses "the
random number generator algorithm used in R". Reading that package's source showed it implements the
**64-bit** Mersenne Twister; R uses the **32-bit** one, seeds it differently, and turns its output into
`sample()` indices by its own rejection method. The same seed therefore cannot give the same numbers. The
package is also licensed under the GPL, which would apply to this program if it were imported. So the
generator in `rrand/` was written from R's own source, with the standard library only, and tested against
values R wrote: it reproduces `runif()` to the last digit and `sample()` exactly
(`docs/spikes/001-environment-and-baseline.md`).

**Design.** Small packages, each usable alone, with no printing and no `os.Exit` outside `main.go`:

| Package | Role | Reusable for |
|---|---|---|
| `rrand` | R's generator: `set.seed`, `runif`, `sample` index | Any Go program that must reproduce R's random numbers |
| `stats` | `Mean`, `StandardDeviation`, `Median`, `MedianInPlace`, defined as R defines them | Any project |
| `bootstrap` | The resampling engine: data, a list of statistics, B, a random stream, workers | Any statistic; any random source |
| `dataset` | Reads and checks a one-column CSV, naming file and line on error | Any one-column numeric file |
| `record` | The one-line result both languages write | Comparing programs |
| `main.go` | The `bootse` command: flags, validation, output, logging, profiles | |
| `internal/compare`, `cmd/compare` | The comparability rule as code | |
| `internal/report`, `cmd/tables` | Generates this README's numbers | |
| `internal/quality` | Checks doc comments and function length | |

Two random streams:

- **R stream** (`-stream r`, the default): one generator, drawn in order, exactly as R does. One core. Use it
  when a result must be checked against R.
- **Block stream** (`-stream block`): every resample has its own generator, derived from the seed and the
  resample's number, so resamples can run on any core in any order. The result for a seed is identical for
  any number of workers. Its draws differ from R's, so its standard errors agree with R's up to Monte Carlo
  error.

A new statistic needs no change to the engine:

```go
trimmedMean := func(resample []float64) float64 {
    slices.Sort(resample)
    trim := len(resample) / 10
    return stats.Mean(resample[trim : len(resample)-trim])
}
standardErrors, err := bootstrap.StandardErrors(data,
    []bootstrap.Statistic{trimmedMean},
    bootstrap.Config{Replicates: 1000, Stream: bootstrap.BlockStream(431), Workers: 8})
```

## Build, run, test

Requirements: Go 1.24 or later. R (4.4 or later, with `boot`) only to re-run the R side.

```bash
git clone https://github.com/mioluigi/go-applied-statistics.git
cd go-applied-statistics
go build -o bootse .        # the program
./bootse                    # analyses the built-in data set (1,000 lognormal observations)
./bootse -data data/normal-10000.csv -replicates 1000 -seed 431
./bootse -data data/normal-10000.csv -stream block -workers 8
./bootse -h                 # every option
```

Results go to standard output; log lines (settings, `read_ms`, `compute_ms`) go to standard error and are
silenced by `-quiet`. `-format tsv` prints the one-line record; `-medians FILE` saves the B resample
medians; `-cpuprofile FILE` and `-memprofile FILE` write profiles for `go tool pprof`.

**Input checks.** A data file is a header line followed by one number per line. Bad input stops the program
before any computation, with a message that names the problem (for a bad value, the file and line): a
missing file, text where a number should be, NaN or infinite values, fewer than 2 observations, fewer than 2
resamples, an unknown stream or format, a seed out of range, more than one worker with the R stream.
Exit codes: **0** success, **2** unusable input, **1** any other failure.

**Creating the executables** (the program is pure Go, so it cross-compiles from any machine):

```bash

scripts/build-macos-app.sh    # dist/BootstrapSE.app: double-click it; it opens Terminal and runs the program
```

**Tests.**

```bash
go vet ./... && go test -race ./...     # needs neither R nor the internet
scripts/check-inputs.sh                 # the 12 data sets match their manifest (size, SHA-256)
scripts/acceptance.sh                   # every acceptance criterion; R-dependent checks say when they are skipped
```

sample median and **every resample median must be identical** as 64-bit values, and summed quantities

a limit set from 2,400 measured comparisons of correct runs (`docs/spikes/002-tolerance.md`). The bootstrap
standard error of the mean is also checked against its theoretical value on every data set.

How to read it:

- **Scenario A** is the like-for-like comparison: one core each. "Jobs to save one dollar" is the number of
  jobs after which the saving adds up to one dollar; multiply by the cost of the rewrite to get its
  break-even.
- **Scenario B** assumes a one-core program can keep all eight cores busy with eight separate jobs without
  slowing down. Comparing like with like (the block stream), eight one-worker jobs side by side cost less
  than one eight-worker job at every size, because eight workers are not eight times faster. Parallel Go is
  for getting one large answer sooner, not for making a batch cheaper.
- Limits: laptop timings, not cloud timings; on-demand prices only; compute only, no storage or transfer;
  one method. The percentages are for this method at these sizes.

## Experience with testing, benchmarking, profiling and logging

**Testing.** Tests came first, with answers known independently of the code: values written by R, exact
rational arithmetic for the mean and standard deviation, hand-computed small cases. The most useful habit was
the **mutation check**: break the code on purpose and see whether a test fails (`docs/mutation-checks.txt`).
It found three gaps: no R reference for sample sizes needing exactly 16 random bits; a test that would not
notice the median and the mean being swapped in the output; and a branch that no input could reach. It also
found that the check itself was wrong once: `go test` answered from its cache, so every mutant seemed to
survive until the runs used `-count=1`.

**What R taught the Go code.** Reproducing R meant learning what R actually does: how `set.seed` scrambles a
seed, that `sample()` uses rejection sampling since R 3.6.0, that `mean()` makes a second correcting pass,
that `median()` averages the two middle values. Each was learned by running R and saving its output, not
from memory of the documentation.

**Benchmarking.** Three kinds of time are kept apart because they answer different questions: whole process,
start-up, and computation. Each whole-process condition was run hundreds of times, with the number of runs
and the standard error of the mean in the tables. Two lessons: the command-line timer's 0.01 s step is too
coarse for a program that starts in milliseconds; and the first official run recorded a very high load
average, traced afterwards to a web browser left open. Its timings were stable, but it was kept only as
evidence (`results/run-1/`) and the measurement was repeated with applications closed.

**Profiling.** `pprof` chose every performance step. The first profile, of the plain implementation
(`docs/performance/profile-before.txt`), pointed at sorting and at memory allocated per resample. The
profile from the first official run pointed somewhere unexpected: the random generator. That led to step 4.

**Logging.** The program logs with `log/slog` to standard error: what it read, the settings, and how long
reading and computing took. Those two timings are what the measurement script collects, so the log is part
of the method, not decoration. Results go to standard output, so a pipeline can use them directly.

**Predictions, checked.** Each prediction made before measuring was written with its conditions and then
compared with the result:

<!-- generated:predictions:start -->
| # | Prediction (with its conditions) | Measured | Outcome |
|---|---|---|---|
| P4 | Go does the course study's resampling volume in under 0.20 s of computation | 0.144 s | **Held** |
| P5 | Computation only, R ÷ Go (one core) is between 2× and 10× at n = 1,000 and n = 10,000 | 3.2× and 2.2× | **Held** |
| P6 | R's start-up is more than 50 % of its whole-process time at n = 100 and under 20 % at n = 100,000 | 76.2 % and 2.9 % | **Held** |

P5 is worth a note: in the first official run it did **not** hold at n = 10,000, where Go's one-core lead
over R was smaller than predicted. It holds in the final run only because of performance step 4. The
prediction had assumed R's cost was mostly interpreter overhead; at large sizes R spends its time in
compiled C, and Go has to earn its lead. Earlier predictions (the course program reproduces its listing; it
takes a few seconds; Go reproduces R's draws) held and are recorded in the spike.

## 1. Problem

A research consultancy runs computer-intensive statistics in R and pays for the cloud time. It asks an
independent data scientist two questions: **how easy is it to use Go in place of R (M1)**, and **how much
cloud cost would that save (M2)**. We answer for one method from Gelman and Vehtari's list, *bootstrapping
and simulation-based inference*, in the form the assignment suggests: a **distribution-free estimate of the
standard error of the median** by bootstrap resampling, for symmetric, positively skewed and negatively
skewed data.

The answer has three parts, and each must be reproducible by a command:

1. **The same analysis in R and in Go, on the same data, with comparable results.**
2. **Time and memory of both**, measured the same way, with start-up separated from computation.
3. **A recommendation with a cost figure** derived from the measurements and from a cloud provider's saved prices.

The spike changed what "comparable" can mean: Go can reproduce R's random draws exactly, so for the same data
and seed the two programs can be required to give **the same standard error of the median, digit for digit**
(spike §6–§7; narrowed after review R1 to *the same resample medians*, with the standard error equal to 1e-12, see §6). The spike also showed the course's jump-start R program spends most of its 5 seconds on data
frames, so the comparison needs an idiomatic R baseline as well (spike §4).

## 3. Definitions (so R and Go compute the same thing)

- **Data set**: n observations x₁…xₙ, n ≥ 2, read from a one-column CSV file.
- **Median**: for odd n the middle value; for even n **the mean of the two middle values** (R's `median`).
- **Bootstrap resample**: n values drawn from the data set with replacement.
- **Bootstrap standard error of a statistic** (the textbook definition, Efron and Tibshirani 1993): draw B
  resamples, compute the statistic on each, and take the **standard deviation of those B values, with
  denominator B − 1**.
- **One set of resamples per run** (review DR-4): after seeding, resample b (b = 1…B) is the next n
  consecutive index draws, and **every statistic is evaluated on that same resample**. The SE of the median
  and the SE of the mean in one run therefore come from the same B resamples, using B × n draws in total.
- The course's R program reports a different quantity (the spread, across 100 fresh samples, of the average
  bootstrap median; spike §4). It is run unchanged and reported as the course's baseline; it is **not** the
  quantity our R and Go programs compute, and the README says so.
- **R stream**: resample indices drawn exactly as R 4.4.2 draws them after `set.seed(seed)` with default
  settings. **Block stream**: every replicate has its own generator, derived only from the seed and the
  replicate number, so replicates can run on different cores in any order.
- **Computation time**: the time to evaluate the B replicates on data already in memory. Reading the file
  and writing the result are outside it (`read_ms` and `compute_ms` in the log).

## 6. Comparability rule (written before measuring; constitution 1.1)

| Quantity | R (`sample()` loop) against Go (R stream) | Against the block stream or `boot` |
|---|---|---|
| n | equal | equal |
| Sample median | **identical** (same double) | identical |
| Sample mean | relative difference ≤ 1e-12 | ≤ 1e-12 |
| **Each of the B resample medians** | **identical** (same double), all B of them | not applicable (different draws) |
| Bootstrap SE of the median | relative difference ≤ **1e-12** | relative difference ≤ **15 %** at B = 1,000 |
| Bootstrap SE of the mean | relative difference ≤ 1e-12 | ≤ 15 % at B = 1,000 |

Why these numbers.

- **Identity for medians.** The same indices select the same values, and a median is a selection (or one
  exact average of two), so no rounding can differ. This is the strong claim: Go drew R's resamples.
- **1e-12 for anything summed** (means, and standard errors, which are standard deviations of B values).
  The sum can differ in the last bit with the width of the accumulator, which depends on the platform; the
  spike saw identity on Apple silicon, and a simulation with extended precision saw at most 1.4e-16 (review
  R1, DR-1). 1e-12 leaves a wide margin and still fails on any real difference.
- **15 % between different random streams** *(changed from 10 % on 2026-11-14, before any official
  comparison; `docs/spikes/002-tolerance.md`)*. Two correct bootstraps with different draws differ by Monte
  Carlo error. Measured on six committed data sets with 200 seeds each at B = 1,000: the standard deviation
  of the relative difference is 2.1 % to 2.6 %, close to the 2.2 % a normal approximation gives, and the
  largest of 2,400 differences was 10.7 %, because the single reference run carries its own error. At 10 %
  a correct implementation would fail about one comparison in several hundred, and the official run makes
  48. 15 % is beyond everything observed and still fails on any gross error (a wrong statistic, sampling
  without replacement, a variance reported as a standard deviation).
- A wrong denominator (B instead of B − 1) hides inside any such tolerance, so it is covered by exact tests.

A second, independent check, on **all 12 data sets** (it holds for any shape): the bootstrap SE of the
**mean** must be within 10 % of √((n − 1) ÷ n) × s ÷ √n, where s is the sample standard deviation.
This limit stays at 10 %: the theoretical value has no Monte Carlo error of its own.

// data set, and can reproduce R's result for the same data and seed number for number.
//
// It is a thin layer: it reads flags, checks them, calls the reusable packages (dataset,
// bootstrap, stats) and prints. Results go to standard output, log lines to standard error.
package main

import (
	"bytes"
	_ "embed"
	"errors"
	"flag"
	"fmt"
	"io"
	"log/slog"
	"os"
	"path/filepath"
	"runtime"
	"runtime/pprof"
	"strings"
	"time"

	"github.com/mioluigi/go-applied-statistics/bootstrap"
	"github.com/mioluigi/go-applied-statistics/dataset"
	"github.com/mioluigi/go-applied-statistics/record"
	"github.com/mioluigi/go-applied-statistics/stats"

// Exit codes (spec FR-9).
const (
	exitSuccess = 0
	exitFailure = 1 // the run could not be completed (for example an output file cannot be written)
	exitInvalid = 2 // the request was not usable: bad flag, bad value, bad data file
)

// builtInName is the committed data set a run without -data analyses.
const builtInName = "lognormal-1000.csv"

//go:embed data/lognormal-1000.csv
var builtInData []byte

// errInvalid marks a request the user must correct; it maps to exitInvalid.
var errInvalid = errors.New("invalid request")

// options holds the checked command-line settings.
type options struct {
	dataPath    string
	replicates  int
	seed        uint32
	streamName  string
	workers     int
	format      string
	mediansPath string
	cpuProfile  string
	memProfile  string
	quiet       bool
}

func main() {
	os.Exit(run(os.Args[1:], os.Stdout, os.Stderr))
}

// run is the whole program with its inputs and outputs passed in, so it can be tested.
func run(arguments []string, stdout, stderr io.Writer) int {
	settings, err := parseOptions(arguments, stderr)
	if errors.Is(err, flag.ErrHelp) {
		return exitSuccess
	}
	if err == nil {
		err = analyse(settings, stdout, stderr)
	}
	if err == nil {
		return exitSuccess
	}
	fmt.Fprintln(stderr, "bootse:", err)
	if errors.Is(err, errInvalid) || errors.Is(err, dataset.ErrInvalid) || errors.Is(err, bootstrap.ErrInvalid) {
		fmt.Fprintln(stderr, "Run \"bootse -h\" for the list of options.")
		return exitInvalid
	}
	return exitFailure
}

// parseOptions reads and checks the flags. Every problem is reported in plain words.
func parseOptions(arguments []string, stderr io.Writer) (options, error) {
	var settings options
	var seed uint64
	flags := flag.NewFlagSet("bootse", flag.ContinueOnError)
	flags.SetOutput(stderr)
	flags.StringVar(&settings.dataPath, "data", "", "data file: a header line, then one number per line (default: built-in "+builtInName+")")
	flags.IntVar(&settings.replicates, "replicates", 1000, "number of bootstrap resamples B (at least 2)")
	flags.Uint64Var(&seed, "seed", 431, "seed of the random stream (0 to 4294967295)")
	flags.StringVar(&settings.streamName, "stream", "r", "random stream: r (reproduces R's sample(), 1 worker) or block (parallel)")
	flags.IntVar(&settings.workers, "workers", 0, "goroutines (default: 1 for -stream r, the number of CPUs for -stream block)")
	flags.StringVar(&settings.format, "format", "text", "output: text (for people) or tsv (one record line, as the R scripts write)")
	flags.StringVar(&settings.mediansPath, "medians", "", "also write the B resample medians to this file, one per line")
	flags.StringVar(&settings.cpuProfile, "cpuprofile", "", "write a CPU profile to this file")
	flags.StringVar(&settings.memProfile, "memprofile", "", "write a memory profile to this file")
	flags.BoolVar(&settings.quiet, "quiet", false, "do not write log lines to standard error")
	if err := flags.Parse(arguments); err != nil {
		if errors.Is(err, flag.ErrHelp) {
			return settings, err
		}
		return settings, fmt.Errorf("%w: %v", errInvalid, err)
	}

	workersGiven := false
	flags.Visit(func(given *flag.Flag) { workersGiven = workersGiven || given.Name == "workers" })
	settings.seed = uint32(seed)
	return settings, checkOptions(&settings, flags.Args(), seed, workersGiven)
}

// checkOptions validates the parsed values and fills in the default worker count.
func checkOptions(settings *options, extra []string, seed uint64, workersGiven bool) error {
	switch {
	case len(extra) > 0:
		return fmt.Errorf("%w: unexpected argument %q (the data file is given with -data)", errInvalid, extra[0])
	case settings.replicates < 2:
		return fmt.Errorf("%w: -replicates is %d; at least 2 resamples are needed for a standard error", errInvalid, settings.replicates)
	case seed > 1<<32-1:
		return fmt.Errorf("%w: -seed is %d; it must be between 0 and 4294967295", errInvalid, seed)
	case settings.streamName != "r" && settings.streamName != "block":
		return fmt.Errorf("%w: -stream is %q; choose r or block", errInvalid, settings.streamName)
	case settings.format != "text" && settings.format != "tsv":
		return fmt.Errorf("%w: -format is %q; choose text or tsv", errInvalid, settings.format)
	case workersGiven && settings.workers < 1:
		return fmt.Errorf("%w: -workers is %d; at least 1 is needed", errInvalid, settings.workers)
	case workersGiven && settings.workers > 1 && settings.streamName == "r":
		return fmt.Errorf("%w: -stream r draws R's numbers in order and runs with 1 worker; "+
			"use -stream block with -workers %d", errInvalid, settings.workers)
	}
	if !workersGiven {
		settings.workers = 1
		if settings.streamName == "block" {
			settings.workers = runtime.NumCPU()
		}
	}
	return nil
}

// analyse reads the data, runs the bootstrap and writes the result.
func analyse(settings options, stdout, stderr io.Writer) error {
	logger := slog.New(slog.NewTextHandler(io.Discard, nil))
	if !settings.quiet {
		logger = slog.New(slog.NewTextHandler(stderr, nil))
	}

	readStart := time.Now()
	name, data, err := readData(settings.dataPath)
	if err != nil {
		return err
	}
	logger.Info("data read", "dataset", name, "n", len(data), "read_ms", milliseconds(time.Since(readStart)))

	stopProfile, err := startCPUProfile(settings.cpuProfile)
	if err != nil {
		return err
	}
	computeStart := time.Now()
	config := bootstrap.Config{Replicates: settings.replicates, Stream: newStream(settings), Workers: settings.workers}
	// The mean is listed first: the median reorders the resample it is given.
	values, err := bootstrap.Replicates(data, []bootstrap.Statistic{stats.Mean, stats.MedianInPlace}, config)
	stopProfile()
	if err != nil {
		return err
	}
	means, medians := values[0], values[1]
	result := record.Record{
		Dataset: name, Observations: len(data), Replicates: settings.replicates,
		Seed: settings.seed, Stream: settings.streamName,
		SEMedian: stats.StandardDeviation(medians), SEMean: stats.StandardDeviation(means),
	}
	logger.Info("bootstrap computed", "replicates", settings.replicates, "stream", settings.streamName,
		"workers", settings.workers, "compute_ms", milliseconds(time.Since(computeStart)))

	result.SampleMedian, result.SampleMean = stats.Median(data), stats.Mean(data)
	if err := writeOutputs(settings, result, medians, stdout); err != nil {
		return err
	}
	return writeMemoryProfile(settings.memProfile)
}

// Package rrand reproduces the random numbers of R's default generator, so that a Go program
// seeded like set.seed(seed) draws exactly what R's runif() and sample() draw.
//
// It follows R's own sources (src/main/RNG.c) for the three steps between set.seed and sample:
// the scrambling of the seed, the conversion of a 32-bit Mersenne Twister output to a number
// in (0, 1), and the rejection sampling of an index. It was checked against R 4.4.2 with
// RNGkind "Mersenne-Twister" and sample.kind "Rejection" (the defaults since R 3.6.0); the
// reference values are in testdata/r-reference.
//
// A Generator is not safe for concurrent use: give each goroutine its own.
package rrand

import "math/bits"

const (
	stateSize  = 624        // words of state in the 32-bit Mersenne Twister
	middleWord = 397        // offset of the word mixed into each new state word
	matrixA    = 0x9908b0df // the twist matrix, applied when the mixed word is odd
	upperMask  = 0x80000000 // most significant bit of a state word
	lowerMask  = 0x7fffffff // the other 31 bits

	seedMultiplier = 69069                  // R's linear congruential scrambler: seed*69069 + 1
	scrambleRounds = 50                     // rounds R applies before filling the state
	toUnitInterval = 2.3283064365386963e-10 // 2^-32, R's scale from a 32-bit output to [0, 1)
	bitsPerDraw    = 16                     // random bits R takes from each uniform number
)

// Generator is a Mersenne Twister in the state R would have after set.seed.
type Generator struct {
	state [stateSize]uint32
	next  int // position of the next unused state word; stateSize means "refill first"
}

// New returns a generator in the state R reaches after set.seed(seed).
func New(seed uint32) *Generator {
	for round := 0; round < scrambleRounds; round++ {
		seed = seedMultiplier*seed + 1
	}
	// R fills 625 words; the first is a position counter that it then overwrites, so the
	// value drawn for it is discarded here.
	seed = seedMultiplier*seed + 1
	generator := &Generator{next: stateSize}
	for word := range generator.state {
		seed = seedMultiplier*seed + 1
		generator.state[word] = seed
	}
	return generator
}

// twist combines the top bit of one state word with the low 31 bits of the next and applies
// the Mersenne Twister's recurrence matrix.
func twist(upper, lower uint32) uint32 {
	mixed := (upper & upperMask) | (lower & lowerMask)
	twisted := mixed >> 1
	if mixed&1 == 1 {
		twisted ^= matrixA
	}
	return twisted
}

// refill replaces all state words with the next 624. The recurrence reads the word
// middleWord places ahead, wrapping around; three plain loops cover the part before the
// wrap, the part after it, and the last word, so no index needs a remainder operation.
func (generator *Generator) refill() {
	state := &generator.state
	word := 0
	for ; word < stateSize-middleWord; word++ {
		state[word] = state[word+middleWord] ^ twist(state[word], state[word+1])
	}
	for ; word < stateSize-1; word++ {
		state[word] = state[word+middleWord-stateSize] ^ twist(state[word], state[word+1])
	}
	state[stateSize-1] = state[middleWord-1] ^ twist(state[stateSize-1], state[0])
	generator.next = 0
}

// uint32 returns the next tempered 32-bit output.
func (generator *Generator) uint32() uint32 {
	if generator.next >= stateSize {
		generator.refill()
	}
	output := generator.state[generator.next]
	generator.next++
	output ^= output >> 11
	output ^= (output << 7) & 0x9d2c5680
	output ^= (output << 15) & 0xefc60000
	output ^= output >> 18
	return output
}

// Float64 returns the next uniform number strictly inside (0, 1), as R's runif(1) does.
func (generator *Generator) Float64() float64 {
	value := float64(generator.uint32()) * toUnitInterval
	// R never returns exactly 0: it nudges it half a step inwards. (R guards 1 the same way,
	// but the largest 32-bit output times 2^-32 is already below 1, so no guard is needed.)
	if value <= 0 {
		return 0.5 * toUnitInterval
	}
	return value
}

// Index returns a uniformly distributed index in [0, n), drawn as R draws each element of
// sample.int(n, size, replace = TRUE) (R's result is this index plus one). n must be at
// least 1 and below 2^31, the range in which R uses this method.
//
// R builds a candidate from just enough random bits to cover n, 16 bits per uniform number,
// and draws again while the candidate is n or more. R takes those 16 bits as
// floor(unif_rand() * 65536); that is exactly the top 16 bits of the generator's 32-bit
// output, so they are taken directly, without a detour through floating point.
func (generator *Generator) Index(n int) int {
	// The number of bits needed to write n-1 equals ceil(log2(n)), R's bit count, and
	// costs no logarithm.
	bitCount := bits.Len(uint(n - 1))
	mask := uint64(1)<<bitCount - 1
	for {
		var candidate uint64
		for filled := 0; filled <= bitCount; filled += bitsPerDraw {
			candidate = candidate<<bitsPerDraw | uint64(generator.uint32()>>bitsPerDraw)
		}
		candidate &= mask
		if candidate < uint64(n) {
			return int(candidate)
		}
	}
}

===== FILE: stats/stats.go =====
// Package stats holds the few descriptive statistics the bootstrap needs, defined exactly as
// R defines them so that results can be compared with R's.
package stats

import (
	"math"
	"slices"
)

// Mean returns the arithmetic mean, or NaN for no values.
//
// Like R's mean(), it makes a second pass that adds the average of the deviations from the
// first estimate. The correction removes most of the rounding error a single sum leaves behind.
func Mean(values []float64) float64 {
	if len(values) == 0 {
		return math.NaN()
	}
	count := float64(len(values))
	sum := 0.0
	for _, value := range values {
		sum += value
	}
	estimate := sum / count

	residual := 0.0
	for _, value := range values {
		residual += value - estimate
	}
	return estimate + residual/count
}

// StandardDeviation returns the sample standard deviation (denominator n - 1), as R's sd()
// does, or NaN for fewer than two values.
//
// It sums squared deviations from the mean. The shortcut "sum of squares minus n times the
// squared mean" is deliberately avoided: it loses most of its digits when the values are
// large compared with their spread.
func StandardDeviation(values []float64) float64 {
	if len(values) < 2 {
		return math.NaN()
	}
	mean := Mean(values)
	sumOfSquares := 0.0
	for _, value := range values {
		deviation := value - mean
		sumOfSquares += deviation * deviation
	}
	return math.Sqrt(sumOfSquares / float64(len(values)-1))
}

// Median returns the middle value, or for an even count the mean of the two middle values,
// as R's median() does. It returns NaN for no values and leaves its argument unchanged.
func Median(values []float64) float64 {
	if len(values) == 0 {
		return math.NaN()
	}
	sorted := slices.Clone(values)
	slices.Sort(sorted)
	lowerMiddle, upperMiddle := (len(sorted)-1)/2, len(sorted)/2
	return (sorted[lowerMiddle] + sorted[upperMiddle]) / 2
}

// MedianInPlace returns the same value as Median without sorting: it finds the middle value
// by selection, which takes time proportional to the number of values instead of n log n.
// It reorders its argument, so it suits a scratch copy such as a bootstrap resample.
func MedianInPlace(values []float64) float64 {
	if len(values) == 0 {
		return math.NaN()
	}
	upperMiddle := len(values) / 2
	selectPosition(values, upperMiddle)
	if len(values)%2 == 1 {
		return values[upperMiddle]
	}
	// After selection everything before upperMiddle is no larger than it, so the lower
	// middle value is the largest of that part.
	lowerMiddle := slices.Max(values[:upperMiddle])
	return (lowerMiddle + values[upperMiddle]) / 2
}

// selectPosition reorders values so that values[position] holds what a full sort would put
// there, with nothing larger before it and nothing smaller after it (Hoare's quickselect).
func selectPosition(values []float64, position int) {
	low, high := 0, len(values)-1
	for low < high {
		pivot := medianOfThree(values[low], values[low+(high-low)/2], values[high])
		left, right := low, high
		for left <= right {
			for values[left] < pivot {
				left++
			}
			for values[right] > pivot {
				right--
			}
			if left <= right {
				values[left], values[right] = values[right], values[left]
				left++
				right--
			}
		}
		// Now values[low..right] <= pivot <= values[left..high]; keep the part with position.
		switch {
		case position <= right:
			high = right
		case position >= left:
			low = left
		default:
			return
		}
	}
}

// medianOfThree returns the middle of three values: a pivot that splits sorted and
// reverse-sorted input evenly.
func medianOfThree(a, b, c float64) float64 {
	return max(min(a, b), min(max(a, b), c))
}

===== FILE: bootstrap/bootstrap.go =====
// Package bootstrap estimates standard errors by bootstrap resampling (Efron and Tibshirani
// 1993): draw B resamples of the data with replacement, evaluate a statistic on each, and
// take the standard deviation of the B values.
//
// The package knows no particular statistic and no particular random generator. A Statistic
// is any function of a sample, and a Stream supplies the random indices; RStream reproduces
// R's sample() exactly, BlockStream is built for parallel runs.
package bootstrap

import (
	"errors"
	"fmt"
	"sync"

	"github.com/mioluigi/go-applied-statistics/stats"
)

// ErrInvalid marks every error caused by unusable arguments. Test for it with errors.Is.
var ErrInvalid = errors.New("invalid bootstrap request")

// A Statistic maps one resample to a number. It receives a scratch copy and may reorder it.
type Statistic func(resample []float64) float64

// An IndexSource draws a uniformly distributed index in [0, n).
type IndexSource interface {
	Index(n int) int
}

// A Stream supplies the random source for each replicate (replicates are numbered from 0).
type Stream interface {
	// Source returns the index source to use for one replicate.
	Source(replicate int) IndexSource
	// Sequential reports whether replicates must be drawn in order from one shared source.
	// A sequential stream runs with exactly one worker.
	Sequential() bool
}

// Config sets the size of a bootstrap run.
type Config struct {
	Replicates int    // B, the number of resamples; at least 2
	Stream     Stream // where the random indices come from
	Workers    int    // goroutines evaluating replicates; at least 1
}

// validate checks a request before any work is done.
func validate(data []float64, statistics []Statistic, config Config) error {
	switch {
	case len(data) < 2:
		return fmt.Errorf("%w: %d observation(s); at least 2 are needed", ErrInvalid, len(data))
	case len(statistics) == 0:
		return fmt.Errorf("%w: no statistic given", ErrInvalid)
	case config.Replicates < 2:
		return fmt.Errorf("%w: %d replicate(s); at least 2 are needed", ErrInvalid, config.Replicates)
	case config.Stream == nil:
		return fmt.Errorf("%w: no random stream given", ErrInvalid)
	case config.Workers < 1:
		return fmt.Errorf("%w: %d worker(s); at least 1 is needed", ErrInvalid, config.Workers)
	case config.Stream.Sequential() && config.Workers > 1:
		return fmt.Errorf("%w: this random stream is sequential and runs with 1 worker, not %d",
			ErrInvalid, config.Workers)
	}
	return nil
}

// Replicates evaluates every statistic on each of config.Replicates resamples of data.
// The result has one row per statistic; row s holds that statistic's value on resamples
// 0, 1, 2, … in that order, whatever the number of workers.
//
// Every statistic sees the same resample, in the order given; a statistic that reorders its
// argument therefore changes the order (not the content) seen by those after it.
func Replicates(data []float64, statistics []Statistic, config Config) ([][]float64, error) {
	if err := validate(data, statistics, config); err != nil {
		return nil, err
	}
	values := make([][]float64, len(statistics))
	for s := range values {
		values[s] = make([]float64, config.Replicates)
	}

	// Each worker owns a contiguous range of replicate numbers and writes each result at its
	// replicate's position, so no result depends on which goroutine finished first.
	var workers sync.WaitGroup
	for worker := 0; worker < config.Workers; worker++ {
		first := worker * config.Replicates / config.Workers
		last := (worker + 1) * config.Replicates / config.Workers
		workers.Add(1)
		go func() {
			defer workers.Done()
			// One scratch buffer per worker, refilled for every replicate: no allocation
			// inside the loop.
			resample := make([]float64, len(data))
			for replicate := first; replicate < last; replicate++ {
				fillResample(resample, data, config.Stream.Source(replicate))
				for s, statistic := range statistics {
					values[s][replicate] = statistic(resample)
				}
			}
		}()
	}
	workers.Wait()
	return values, nil
}

// fillResample overwrites resample with len(resample) values drawn from data with replacement.
func fillResample(resample, data []float64, source IndexSource) {
	for i := range resample {
		resample[i] = data[source.Index(len(data))]
	}
}

// StandardErrors returns the bootstrap standard error of each statistic: the standard
// deviation (denominator B - 1) of its values over the resamples.
func StandardErrors(data []float64, statistics []Statistic, config Config) ([]float64, error) {
	values, err := Replicates(data, statistics, config)
	if err != nil {
		return nil, err
	}
	standardErrors := make([]float64, len(values))
	for s, row := range values {
		standardErrors[s] = stats.StandardDeviation(row)
	}
	return standardErrors, nil
}

package bootstrap

import (
	"math/rand/v2"

	"github.com/mioluigi/go-applied-statistics/rrand"
)

// rStream draws every replicate from one generator, in order: exactly what a loop of
// sample(x, n, replace = TRUE) does in R after set.seed.
type rStream struct {
	generator *rrand.Generator
}

// RStream returns the stream that reproduces R: for the same seed and data, replicate b is
// the b-th resample R would draw after set.seed(seed). It is sequential (one worker).
func RStream(seed uint32) Stream {
	return rStream{generator: rrand.New(seed)}
}

// Source returns the shared generator: every replicate continues where the last one stopped.
func (stream rStream) Source(int) IndexSource { return stream.generator }

// Sequential reports true: the draws of one replicate follow those of the one before.
func (stream rStream) Sequential() bool { return true }

// blockStream gives every replicate its own generator, derived from the seed and the
// replicate number alone, so replicates can be drawn in any order and on any goroutine.
type blockStream struct {
	seed uint32
}

// BlockStream returns the stream for parallel runs. For a given seed its results do not
// depend on the number of workers. Its draws differ from R's, so its standard errors agree
// with RStream's only up to Monte Carlo error; use RStream when a result must be checked
// against R number for number.
func BlockStream(seed uint32) Stream {
	return blockStream{seed: seed}
}

// Source returns a new PCG generator (math/rand/v2) for one replicate. The pair (seed,
// replicate) is unique, and SplitMix64 turns it into two well-mixed seed words, so
// neighbouring replicates do not start from neighbouring generator states.
func (stream blockStream) Source(replicate int) IndexSource {
	key := uint64(stream.seed)<<32 | uint64(uint32(replicate))
	return pcgSource{rand.New(rand.NewPCG(splitMix64(key), splitMix64(^key)))}
}

// Sequential reports false: each replicate is independent of the others.
func (stream blockStream) Sequential() bool { return false }

// pcgSource adapts a standard-library generator to IndexSource.
type pcgSource struct {
	generator *rand.Rand
}

// Index returns an unbiased index in [0, n).
func (source pcgSource) Index(n int) int { return source.generator.IntN(n) }

// splitMix64 is the standard 64-bit mixing function (Steele, Lea and Flood 2014): it maps
// consecutive inputs to outputs that look unrelated.
func splitMix64(x uint64) uint64 {
	x += 0x9e3779b97f4a7c15
	x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9
	x = (x ^ (x >> 27)) * 0x94d049bb133111eb
	return x ^ (x >> 31)
}

// Package dataset reads the one-column CSV files the analysis runs on: a header line, then
// one number per line. It validates as it reads, so a bad file is reported with its line.
package dataset

import (
	"bufio"
	"errors"
	"fmt"
	"io"
	"math"
	"os"
	"strconv"
	"strings"
)

// MinObservations is the fewest observations a data set may have: a standard error needs two.
const MinObservations = 2

// ErrInvalid marks every error caused by the content of a data set (as opposed to a file
// that cannot be opened). Test for it with errors.Is.
var ErrInvalid = errors.New("invalid data set")

// ReadFile reads the data set stored at path.
func ReadFile(path string) ([]float64, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, fmt.Errorf("cannot read data set: %w", err)
	}
	defer file.Close()
	return Read(file, path)
}

// Read parses a data set from reader; name is used in error messages.
//
// The first line must be a header (any text that is not a number), matching what the R
// scripts skip. Blank lines are ignored, and Windows line endings are accepted. Every other
// line must be one finite number.
func Read(reader io.Reader, name string) ([]float64, error) {
	var values []float64
	scanner := bufio.NewScanner(reader)
	for lineNumber := 1; scanner.Scan(); lineNumber++ {
		text := strings.TrimSpace(scanner.Text())
		value, parseError := strconv.ParseFloat(text, 64)
		switch {
		case lineNumber == 1 && parseError == nil:
			return nil, fmt.Errorf("%w: %s, line 1: found the number %q where the header line should be; "+
				"add a header such as \"value\"", ErrInvalid, name, text)
		case lineNumber == 1 || text == "":
			continue
		case parseError != nil:
			return nil, fmt.Errorf("%w: %s, line %d: %q is not a number", ErrInvalid, name, lineNumber, text)
		case math.IsNaN(value) || math.IsInf(value, 0):
			return nil, fmt.Errorf("%w: %s, line %d: %q is not a finite number", ErrInvalid, name, lineNumber, text)
		}
		values = append(values, value)
	}
	if err := scanner.Err(); err != nil {
		return nil, fmt.Errorf("cannot read data set %s: %w", name, err)
	}
	if len(values) < MinObservations {
		return nil, fmt.Errorf("%w: %s has %d observation(s); at least %d are needed",
			ErrInvalid, name, len(values), MinObservations)
	}
	return values, nil
}

# bootstrap-se.R: bootstrap standard errors of the median and the mean, in idiomatic base R.
#
# Usage: Rscript r/bootstrap-se.R <data.csv> [replicates = 1000] [seed = 431] [medians file]
#
# Method (Efron and Tibshirani 1993): draw B resamples of the data with replacement, compute
# the statistic on each, and report the standard deviation of the B values.
#
# Output, one tab-separated line on standard output (the same record the Go program writes):
#   data set, n, B, seed, stream, sample median, SE median, sample mean, SE mean
# Timing goes to standard error: read_ms (reading the file) and compute_ms (the B resamples).
# With a fourth argument, the B resample medians are written to that file, one per line.

arguments <- commandArgs(trailingOnly = TRUE)
fail <- function(message) {
    cat("bootstrap-se.R: ", message, "\n", sep = "", file = stderr())
    quit(status = 2)
}
if (length(arguments) < 1) fail("usage: Rscript r/bootstrap-se.R <data.csv> [replicates] [seed] [medians file]")
dataFile <- arguments[1]
replicates <- if (length(arguments) >= 2) suppressWarnings(as.integer(arguments[2])) else 1000L
seed <- if (length(arguments) >= 3) suppressWarnings(as.integer(arguments[3])) else 431L
mediansFile <- if (length(arguments) >= 4) arguments[4] else NA
if (!file.exists(dataFile)) fail(paste("cannot read", dataFile))
if (is.na(replicates) || replicates < 2) fail("replicates must be a whole number of at least 2")
if (is.na(seed)) fail("seed must be a whole number")

readStart <- proc.time()[["elapsed"]]
x <- scan(dataFile, what = numeric(), skip = 1, quiet = TRUE)
n <- length(x)
readMs <- (proc.time()[["elapsed"]] - readStart) * 1000
if (n < 2) fail("the data set needs at least 2 observations")

# One set of B resamples; both statistics are computed on each resample.
computeStart <- proc.time()[["elapsed"]]
set.seed(seed)
medians <- numeric(replicates)
means <- numeric(replicates)
for (b in seq_len(replicates)) {
    resample <- sample(x, n, replace = TRUE)
    means[b] <- mean(resample)
    medians[b] <- median(resample)
}
standardErrorMedian <- sd(medians)
standardErrorMean <- sd(means)
computeMs <- (proc.time()[["elapsed"]] - computeStart) * 1000

exact <- function(value) sprintf("%.17g", value)
cat(paste(basename(dataFile), n, replicates, seed, "r",
          exact(median(x)), exact(standardErrorMedian),
          exact(mean(x)), exact(standardErrorMean), sep = "\t"), "\n", sep = "")
cat(sprintf("read_ms=%.3f compute_ms=%.3f\n", readMs, computeMs), file = stderr())
if (!is.na(mediansFile)) writeLines(exact(medians), mediansFile)

# bootstrap-se-boot.R: the same analysis as bootstrap-se.R with the CRAN package "boot"
# (Davison and Hinkley 1997; https://cran.r-project.org/package=boot).
#
# Usage: Rscript r/bootstrap-se-boot.R <data.csv> [replicates = 1000] [seed = 431]
#
# boot() draws all resample indices in one call and deals them to replicates in its own
# order, so for the same seed its resamples differ from a sample() loop's. Its standard
# errors agree with bootstrap-se.R statistically, not digit for digit; the output's "stream"
# field says "boot" to mark that.

arguments <- commandArgs(trailingOnly = TRUE)
fail <- function(message) {
    cat("bootstrap-se-boot.R: ", message, "\n", sep = "", file = stderr())
    quit(status = 2)
}
if (length(arguments) < 1) fail("usage: Rscript r/bootstrap-se-boot.R <data.csv> [replicates] [seed]")
dataFile <- arguments[1]
replicates <- if (length(arguments) >= 2) suppressWarnings(as.integer(arguments[2])) else 1000L
seed <- if (length(arguments) >= 3) suppressWarnings(as.integer(arguments[3])) else 431L
if (!file.exists(dataFile)) fail(paste("cannot read", dataFile))
if (is.na(replicates) || replicates < 2) fail("replicates must be a whole number of at least 2")
if (is.na(seed)) fail("seed must be a whole number")

loadStart <- proc.time()[["elapsed"]]
suppressPackageStartupMessages(library(boot))
loadMs <- (proc.time()[["elapsed"]] - loadStart) * 1000

readStart <- proc.time()[["elapsed"]]
x <- scan(dataFile, what = numeric(), skip = 1, quiet = TRUE)
n <- length(x)
readMs <- (proc.time()[["elapsed"]] - readStart) * 1000
if (n < 2) fail("the data set needs at least 2 observations")

# The statistic receives the data and the indices of one resample; it returns both values.
medianAndMean <- function(data, indices) {
    resample <- data[indices]
    c(median(resample), mean(resample))
}

computeStart <- proc.time()[["elapsed"]]
set.seed(seed)
result <- boot(x, medianAndMean, R = replicates)
standardErrorMedian <- sd(result$t[, 1])
standardErrorMean <- sd(result$t[, 2])
computeMs <- (proc.time()[["elapsed"]] - computeStart) * 1000

exact <- function(value) sprintf("%.17g", value)
cat(paste(basename(dataFile), n, replicates, seed, "boot",
          exact(median(x)), exact(standardErrorMedian),
          exact(mean(x)), exact(standardErrorMean), sep = "\t"), "\n", sep = "")
cat(sprintf("load_ms=%.3f read_ms=%.3f compute_ms=%.3f\n", loadMs, readMs, computeMs), file = stderr())

# time_run GROUP IMPLEMENTATION DATASET N RUN COMMAND...: runs the command once under the time
# tool and appends one line to runs.tsv. The program's own log gives read_ms and compute_ms.
time_run() {
  local group="$1" implementation="$2" dataset="$3" n="$4" run="$5"; shift 5
  local log="$work/run.log"
  if ! $time_tool "$@" > /dev/null 2> "$log"; then
    tail -n 15 "$log" >&2
    fail "$implementation failed on $dataset (run $run)."
  fi
  field() { sed -n "s/.*$1=\([0-9.eE+-]*\).*/\1/p" "$log" | tail -n 1; }
  local real footprint
  real="$(awk '/ real /{print $1}' "$log")"
  footprint="$(awk '/peak memory footprint/{print $1}' "$log")"
  # Fail on the first run, not after half an hour, if the time tool's output is not understood.
  if [ -z "$real" ] || [ -z "$footprint" ]; then
    cat "$log" >&2
    fail "could not read the time or memory of $implementation from the time tool's output (above)."
  fi
  case "$implementation" in r-loop|r-boot|go-r|go-block-1|go-block-multi)
    [ -n "$(field compute_ms)" ] || { cat "$log" >&2; fail "$implementation logged no compute_ms."; } ;;
  esac
  printf '%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\n' "$group" "$implementation" "$dataset" "$n" "$run" \
    "$real" "$(awk '/ real /{print $3}' "$log")" "$(awk '/ real /{print $5}' "$log")" \
    "$(awk '/maximum resident set size/{print $1}' "$log")" "$footprint" \
    "$(field read_ms)" "$(field compute_ms)" >> "$runs_file"
}

# run_implementation GROUP IMPLEMENTATION FILE N RUN: one timed run of one implementation.
run_implementation() {

    r-loop)       time_run "$group" "$implementation" "$file" "$n" "$run" Rscript r/bootstrap-se.R "data/$file" "$replicates" "$seed" ;;
    r-boot)       time_run "$group" "$implementation" "$file" "$n" "$run" Rscript r/bootstrap-se-boot.R "data/$file" "$replicates" "$seed" ;;
    go-r)         time_run "$group" "$implementation" "$file" "$n" "$run" "$work/bootse" -format tsv -data "data/$file" -replicates "$replicates" -seed "$seed" ;;
    go-block-1)   time_run "$group" "$implementation" "$file" "$n" "$run" "$work/bootse" -format tsv -data "data/$file" -replicates "$replicates" -seed "$seed" -stream block -workers 1 ;;
    go-block-multi) time_run "$group" "$implementation" "$file" "$n" "$run" "$work/bootse" -format tsv -data "data/$file" -replicates "$replicates" -seed "$seed" -stream block -workers "$workers" ;;
    *) fail "unknown implementation $implementation" ;;
  esac
}
